# Scenario Writer (Stage 1)

사용자 여정을 narrative + step list로 캡처하는 첫 단계 스킬.

## When to invoke

**Trigger on:**
- "시나리오 / 사용자 여정 / 유저 저니 / user journey / use case 써줘 / 정리하자"
- "회원가입부터 ~까지 흐름을 짜자"
- `/scenario` 슬래시 커맨드

**Do NOT trigger on:**
- 이미 시나리오가 있고 와이어프레임/PRD 단계인 경우
- "어떻게 동작해?" 같은 코드 동작 설명 요청

## 핵심 원칙

1. **페르소나 우선** — 누구의 시나리오인지 명확히 하지 않고 쓰지 않음
2. **시작-중간-끝이 명확** — 진입점(예: 회원가입), 핵심 업무, 종료 조건
3. **사용자 행동 ↔ 시스템 반응을 쌍으로** — "사용자가 X 한다" + "시스템이 Y 한다"
4. **분기 명시** — 성공/실패/대기/취소 등 갈라지는 흐름
5. **추정·미정 마킹** — `🔸 [추정]`, `🟡 [확인 필요]` 사용 (`.claude/CLAUDE.md` 규칙)
6. **빈칸 환각 금지** — 사용자가 안 준 단계는 만들지 않음

## Workflow

### Step 0: 작업 폴더 결정

먼저 작업 슬러그를 정합니다 (예: `meeting-notes-flow`). 다음 위치를 사용:
```
docs/planning/<YYYY-MM-DD>-<slug>/01-scenarios.md
```

폴더가 없으면 생성. 이미 있으면 기존 파일을 읽고 업데이트 모드로 진행.

### Step 1: 페르소나 인터뷰 (AskUserQuestion)

다음을 물어봅니다:
- 이 시나리오의 주 사용자(페르소나)는 누구?
- 1인용 / 팀용 / 멀티유저?
- 핵심 업무(이 시나리오가 끝났을 때 사용자가 무엇을 달성했나)?

답이 추상적이면 follow-up 1회.

### Step 2: 핵심 흐름 골격 잡기 (AskUserQuestion)

- 진입점은? (회원가입 / 로그인 / 초대 링크 / 외부 공유 링크 등)
- 첫 사용시(onboarding)와 재방문시 시나리오가 다른가?
- 핵심 업무까지의 주요 마일스톤 3~5개?
- 종료 조건은? (성공적으로 끝난 상태)

이 답을 바탕으로 시나리오 골격을 한 줄씩 요약해서 사용자에게 다시 확인.

### Step 3: 단계별 행동/반응 작성

각 단계별로:

```
### Step N: <단계 이름>

**사용자**: <사용자가 무엇을 한다>
**시스템**: <시스템이 무엇으로 응답한다>
**전제조건**: <이 단계 진입 조건>
**완료조건**: <다음 단계로 넘어가는 조건>
**관련 화면**: 🔸 [추정: <화면명>]  ← 와이어프레임 단계에서 확정
```

한 단계 작성 후 사용자에게 확인 → 다음 단계.

### Step 4: 분기 시나리오 정리

성공 시나리오(happy path)를 다 적은 뒤, 분기를 별도 섹션으로:

- **실패 시나리오**: 네트워크 오류, 권한 거부, 입력 오류 등
- **대기 시나리오**: 비동기 처리, 외부 응답 대기
- **취소 시나리오**: 사용자가 중간에 그만두는 경우

각 분기마다 "이 상황에서 시스템은 어떻게 동작?" 사용자에게 확인.

### Step 5: 산출 파일 저장

다음 구조로 `01-scenarios.md`에 저장:

```markdown
# 사용자 시나리오 — <제품/기능명>

## 메타
- 작성일: YYYY-MM-DD
- 페르소나: <한 줄 묘사>
- 핵심 업무: <한 줄>

## 0. 시나리오 개요 (한 단락)

<사용자가 어디서 시작해서 무엇을 달성하고 끝나는지>

## 1. 메인 시나리오 (Happy Path)

### Step 1: <이름>
**사용자**: ...
**시스템**: ...
**전제조건**: ...
**완료조건**: ...
**관련 화면**: 🔸 [추정: ...]

### Step 2: ...

## 2. 분기 시나리오

### 2.1 실패: ...
### 2.2 대기: ...
### 2.3 취소: ...

## 3. 핵심 데이터 (스케치)

시나리오 진행 중 등장하는 데이터를 가볍게 나열. 정식 모델링은 03-data-model.md에서.

- User: 이메일, 이름, 가입일, ...
- Meeting: 제목, 시작시각, 종료시각, 참석자, ...
- 🟡 [확인 필요: ...]

## 4. Open Questions

- 🟡 ...
- 🟡 ...

## 5. 다음 단계로 넘기는 입력 요약

와이어프레임 단계에서 식별해야 할 화면 목록:
- 🔸 [추정] 회원가입 화면
- 🔸 [추정] ...
```

### Step 6: 다음 단계 안내

작성 완료 후 사용자에게:
> "시나리오 작성 완료. 다음은 와이어프레임 단계입니다. `/wireframe` 또는 `wireframe-designer` 스킬로 이어갈 수 있습니다."

## 안 좋은 패턴 (피해야 함)

- ❌ 페르소나도 안 정하고 단계부터 쓰기
- ❌ "사용자가 잘 사용한다" 같은 모호한 행동 묘사 — "사용자가 [구체적 버튼/입력] 을 한다"로
- ❌ 분기 누락 (happy path만 있는 시나리오는 합격이 아님)
- ❌ 추정/미정 마킹 없이 단정적으로 쓰기
- ❌ 화면 디자인 디테일 들어가기 — 시나리오 단계는 무엇을 하는지에 집중, 어떻게 보이는지는 와이어프레임 단계
