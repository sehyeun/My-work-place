**중요**: 종료 조건이 "PR 생성"이 아니라 "PR 머지"이므로, 시나리오에 **팀의 리뷰·머지 단계**가 포함되어야 함. 단, 머지 자체는 사람의 행동이라 시스템 자동화 범위는 PR 생성까지.

| 요약 LLM | Anthropic Claude Sonnet 4.6 |
| 업로드 방식 | GitHub PR 생성 |

### Stage 1 시나리오 컨펌 결정 (2026-05-24)

`01-scenarios.md`의 Open Questions 8건이 해소되어 다음으로 확정되었습니다.
이후 단계(와이어프레임/데이터/인터랙션/PRD)는 이 결정을 입력으로 합니다.

| # | 항목 | 결정 | 후속 단계 영향 |
|---|------|------|--------------|
| 1 | 가입 완료 직후 동작 | **자동 로그인** 후 대시보드 진입 | Stage 2: 가입 폼 → 대시보드 직링크. Stage 4: 가입 API 응답에 세션 쿠키 포함. |
| 2 | 회의 정보 입력 항목 | **기본 필드만** (회의 제목, 일시, 참석자) — 회의 유형/태그·프로젝트 선택 등 추가 메타 없음 | Stage 3: Meeting 엔티티에 type/tag/project 컬럼 도입 보류. |
| 3 | 평균 회의 길이 | **1시간 ~ 2시간** | Stage 3/4: Whisper 25MB 제한 대응 청크 분할 **필수**. 비동기 워커 타임아웃 설계 영향. |
| 4 | 처리 완료 알림 채널 | **인앱 + 이메일 + Slack** 모두 | Stage 3: NotificationChannel 엔티티 + 사용자 채널 설정. Stage 4: 채널별 발신 어댑터. |
| 5 | 회의록 본문 수정 방식 | **앱 내 인라인 편집 + GitHub PR 동기화** | Stage 2: 상세 페이지에 편집 모드. Stage 4: 편집→PR 커밋 푸시 흐름 추가. |
| 6 | 실패 자동 복구 범위 | **청크 분할 + 재시도 + 결과 품질 보정** (화자 분리, 속기어 교정, 종료 감지 등) | Stage 4: 처리 파이프라인에 품질 보정 단계 명시. 비용/지연 가산 PRD 반영. |
| 7 | 회의록 저장 리포 매핑 | **시스템 전체 단일 리포** (관리자가 1개 리포 사전 등록) | Stage 3: 사용자별/팀별 RepoMapping 엔티티 불필요. Stage 4: 리포 선택 UI 제거. |
| 8 | 본 컨텍스트 문서 정정 | **00-context.md 갱신 우선** 후 와이어프레임 진행 | 본 문서가 그 결과물. |

## 추정·미정 사항

- 🟡 [확인 필요: V1 페르소나 범위 — PM·기획자 단일이 시나리오 기본 가정. 개발팀(스탠드업)·외부 미팅 매니저 포함 여부는 PRD 단계에서 최종 결정]
- 🟡 [확인 필요: 동시 사용자 규모 — 비동기 워커 개수 / 큐 설계에 영향. 현재 추정 불가, PRD 비기능 요구에서 다룸]
- 🟡 [확인 필요: Slack 연동 방식 — 워크스페이스 단위 1회 설치 vs 채널별 봇 토큰. 인터랙션 단계에서 결정]
- 🟡 [확인 필요: 인앱 편집 시 충돌 처리 — 사용자가 앱에서 편집 중인데 PR에 외부 커밋이 들어오는 경우. 인터랙션 단계에서 결정]
- 🔸 [추정: V1은 한국어 회의 우선, 다국어는 Phase 5+]
- 🔸 [추정: 결과 품질 보정은 Claude 후처리 프롬프트 단계에서 수행 (별도 모델 없이)]

## 후속 단계 입력 요약

이 컨텍스트가 다음 단계들에 어떻게 흘러가는지:

| Stage | 본 컨텍스트의 영향 |
|-------|------------------|
| 1. Scenario | ✅ **완료** (`01-scenarios.md`). 페르소나(PM·기획자) 중심 가입~PR 머지 흐름. Open Questions 8건 모두 해소. |
| 2. Wireframe | 가입 폼 → 대시보드 자동 진입, 대시보드(빈/리스트), 회의 정보 입력(기본 필드), 녹음, 상세(읽기+편집 모드), 알림 채널 설정. 리포 선택 UI 없음. |
| 3. Data Model | User, InviteToken, Meeting(기본 필드만), MeetingFile(청크 메타), GitHubPR, NotificationChannel(인앱/이메일/Slack), AuditLog. 리포 매핑 엔티티 불필요(시스템 단일). |
| 4. Interaction | 가입→자동 로그인, 업로드 청크 분할, Whisper→Claude(품질 보정 포함)→PR 비동기 파이프라인, 인앱 편집→PR 푸시 동기화, 3채널 알림 발신, PR 머지 웹훅. |
| 5. PRD | PM·기획자 V1 시나리오 + Non-goal 명시(2차 페르소나, 다국어, 회의 유형 분류, 사용자별 리포 선택). Open Questions 섹션에 위 미정 4건 남김. |
