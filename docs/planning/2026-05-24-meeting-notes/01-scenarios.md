## 메인 시나리오 (End-to-End)

> 💬 한 줄 요약: PM 김PM이 관리자 초대로 가입한 뒤, 주간 기획 회의를 앱으로 녹음하면 AI가 정리한 회의록이 GitHub PR로 올라오고, 팀이 리뷰·머지하여 `docs/meetings/`에 영구 보관된다.

### 등장 인물

- **김PM** (주인공, PM·기획자)
- **이팀장** (시스템 관리자, 가입 초대 발송자) — 1회만 등장
- **박개발** (참석자/리뷰어, 같은 팀원) — 머지 단계에서 등장
- **시스템** (회의록 자동화 앱)
- **외부 서비스**: Whisper API, Claude API, GitHub

---

### Step 0. 가입 초대 수신 (1회성)

- **상황**: 이팀장(관리자)이 김PM의 회사 이메일로 가입 초대 링크를 발송한 상태.
- **행동**: 김PM이 이메일에서 "가입하기" 버튼 클릭.
- **시스템 반응**: 초대 토큰을 검증하고 가입 폼 화면으로 이동.
- **결과**: 가입 폼 진입.

### Step 1. 회원가입

- **화면**: 가입 폼
- **입력 항목**:
  - 이메일 (초대된 주소가 read-only로 표시, ID로 사용)
  - 패스워드 + 패스워드 확인
  - 이름
  - 부서 (유닛 / 팀명)
- **행동**: 정보 입력 → "가입 완료" 클릭
- **시스템 반응**: 계정 생성 → **자동 로그인** 후 대시보드로 이동 (Stage 1 컨펌 #1).
- **결과**: 인증된 세션 보유, Step 3(대시보드)로 직진.

### Step 2. 로그인 (재방문 사용자 진입점)

- **상황**: 최초 가입 사용자는 Step 1에서 자동 로그인되어 이 단계를 건너뜀. 재방문(세션 만료 또는 로그아웃 후)일 때만 거침.
- **행동**: 이메일 + 패스워드 입력 → "로그인".
- **시스템 반응**: 인증 성공 → 대시보드로 이동.
- **결과**: 인증된 세션 보유.

### Step 3. 대시보드 첫 진입 + 온보딩 안내

- **화면**: 대시보드 (회의록 목록)
- **첫 사용자 분기**: 회의록이 0건이므로 **빈 상태(empty state)** 노출:
  - "아직 녹음된 회의가 없어요"
  - 큰 CTA: "첫 회의 녹음하기"
  - 보조 가이드 툴팁(또는 짧은 3-step 미니 투어): "녹음 → AI 정리 → GitHub PR"
- **재방문 사용자**: 최근 회의록 카드 리스트가 표시되고, 상단에 "새 회의 녹음" 버튼만 노출.
- **행동**: "새 회의 녹음" 또는 "첫 회의 녹음하기" 클릭.
- **결과**: 회의 정보 입력 화면 진입.

### Step 4. 회의 정보 입력

- **화면**: 새 회의 모달 또는 페이지
- **입력 항목** (Stage 1 컨펌 #2: 기본 필드만 유지, 회의 유형/태그·프로젝트 분류 없음):
  - 회의 제목 (필수)
  - 회의 일시 (기본값: 현재 시각, 수정 가능)
  - 참석자 (선택, 추후 PR 리뷰어로 자동 할당)
- **행동**: 입력 후 "녹음 시작".
- **시스템 반응**: 브라우저 마이크 권한 요청 다이얼로그.

### Step 5. 마이크 권한 + 녹음 시작

- **행동**: 마이크 권한 허용.
- **시스템 반응**:
  - 녹음 시작
  - 화면에 실시간 파형(waveform) + 경과 타이머 표시
  - 일시정지/재개/종료 버튼 노출
- **결과**: 녹음 진행 중.

### Step 6. 회의 진행

- **상황**: 회의를 진행하며 김PM은 노트북을 회의실 가운데 놓아둠.
- **사용자 인터랙션**: 거의 없음. 필요 시 일시정지/재개.
- **시스템 반응**: 클라이언트 측에서 청크 단위 녹음 + 자동 임시 저장 (네트워크 끊김 대비).
- **회의 길이 가정** (Stage 1 컨펌 #3): 평균 **1~2시간**. Whisper 25MB 제한으로 **청크 분할 필수** — 클라이언트는 ~10분 단위 청크로 분할 업로드, 서버에서 순차 STT 후 병합.

### Step 7. 녹음 종료 + 업로드

- **행동**: "녹음 종료" 클릭 → 확인 다이얼로그 → 확정.
- **시스템 반응**:
  - 녹음 파일 서버에 업로드
  - 업로드 진행률 표시 (퍼센트 + 예상 시간)
  - 업로드 완료 시 처리 큐 등록 → "처리 중" 상태로 전환
- **결과**: 사용자는 다른 일을 하러 갈 수 있음.

### Step 8. 대시보드 복귀 + 처리 상태 확인

- **화면**: 대시보드
- **표시**: 방금 끝낸 회의가 카드로 표시 + 상태 배지 = "🎙️ 처리 중" (또는 "STT 변환 중" → "요약 생성 중" → "PR 생성 중" 세부 단계)
- **사용자 행동**: 화면을 닫거나, 새로고침으로 상태 확인.
- **시스템 백엔드** (비동기 워커):
  1. Whisper로 STT
  2. Claude로 요약·구조화 (제목/참석자/안건/결정/액션아이템)
  3. 마크다운 회의록 생성
  4. GitHub PR 생성 (지정 리포의 `docs/meetings/YYYY-MM-DD-<slug>.md`)

### Step 9. 처리 완료 알림 수신

- **알림 채널** (Stage 1 컨펌 #4: 3채널 모두 발신):
  - **인앱**: 대시보드 카드 상태가 "✅ 완료"로 변경 + 종 아이콘 뱃지.
  - **이메일**: 가입 이메일로 회의록 링크 발송.
  - **Slack**: 사용자가 설정에 등록한 워크스페이스/채널로 발송.
- **사용자 설정**: 채널별 ON/OFF 가능 (인앱은 항상 ON).
- **알림 내용**: 회의 제목, 처리 시간, "회의록 보기" 링크, GitHub PR 링크.
- **행동**: 김PM이 알림(또는 카드)을 클릭.

### Step 10. 회의록 상세 페이지 미리보기

- **화면**: 회의록 상세 (읽기 모드 / 편집 모드 전환)
- **표시 (읽기 모드)**: 마크다운 렌더링된 회의록, STT 원문 (펼치기), GitHub PR 링크, "편집" 버튼, 다시 처리 버튼.
- **김PM의 검토**: 내용 빠르게 훑어봄 → 사실관계 확인.
- **편집 모드** (Stage 1 컨펌 #5):
  - "편집" 클릭 → 마크다운 인라인 에디터 진입.
  - "저장" 시 시스템이 회의록 PR 브랜치에 **새 커밋을 자동 푸시** → 앱과 GitHub PR이 동기화됨.
  - PR이 이미 머지된 회의록은 편집 불가 (Step 12 종료 후 잠금).

### Step 11. GitHub PR 리뷰 요청

- **행동**: "GitHub PR 열기" 클릭 → GitHub로 이동.
- **상황**: PR 본문에 회의 요약 + 참석자 자동 멘션이 들어가 있음.
- **김PM 행동**: 참석자 박개발을 리뷰어로 지정 (Step 4에서 참석자 입력했다면 자동 지정).
- **결과**: 박개발에게 GitHub 알림이 전달됨.

### Step 12. 팀 리뷰 + 머지 (종료 조건)

- **박개발 행동**: PR에서 회의록 확인 → 코멘트로 수정 제안 또는 직접 커밋.
- **김PM 행동**: 수정 반영(또는 박개발이 직접) → "Merge" 클릭.
- **결과**:
  - `docs/meetings/2026-05-24-weekly-planning.md`가 main 브랜치에 영구 보관
  - 시스템은 PR 머지 웹훅(또는 폴링)으로 회의록 상태를 "📦 보관 완료"로 갱신
- **시나리오 종료** ✅

## 분기 시나리오 (Branches)

### B1. 업로드 네트워크 실패 (Step 7 분기)

- **트리거**: 녹음 종료 후 업로드 중 네트워크 끊김.
- **시스템**: 로컬에 임시 저장된 녹음 파일을 보관 + "업로드 실패, 재시도" 토스트.
- **사용자 행동**: "재시도" 클릭 또는 자동 재시도 (지수 백오프).
- **종료**: 업로드 성공 시 Step 8로 합류.
- 🟡 [확인 필요: 브라우저 종료 후에도 임시 파일 복구 가능 여부 — IndexedDB 등 활용 여부]

### B2. AI 처리 실패 (Step 8 분기)

- **트리거**: Whisper 한도 초과, Claude API 일시 장애, GitHub PR 생성 실패 등.
- **시스템 자동 복구** (Stage 1 컨펌 #6 — V1 포함 범위):
  1. **청크 분할**: 파일이 Whisper 25MB 초과 시 자동 분할 후 재요청.
  2. **지수 백오프 재시도**: 일시적 5xx/429 에러는 자동 재시도(최대 3회, 2/4/8초 간격).
  3. **결과 품질 보정** (Claude 후처리 프롬프트로 수행):
     - 화자 분리 보정 (Whisper의 발화자 라벨 정리)
     - 한국어 속기어/오타 자동 교정 (예: "그쵸"→"그렇죠")
     - 회의 종료 시점 감지 ("오늘은 여기까지" 등 종결 표현 인식)
- **자동 복구 실패 시**: 카드 상태가 "⚠️ 실패" + 원인 메시지("STT 한도 초과", "GitHub 권한 만료" 등) + "다시 시도" 버튼.
- **사용자 행동**: 원인에 따라 수동 재시도 / 관리자 문의.

### B3. 처리 시간 지연 (Step 8 분기)

- **트리거**: 1시간짜리 회의 등 처리 시간이 5분을 초과.
- **시스템**: "예상보다 시간이 걸리고 있어요" 안내 + 진행률 표시.
- **사용자 행동**: 그냥 닫고 다른 일. 완료 시 Step 9 알림으로 복귀.

### B4. 녹음 중 취소 (Step 6 분기)

- **트리거**: 사용자가 회의 중에 "녹음 취소" 클릭.
- **시스템**: 확인 다이얼로그("녹음한 내용이 삭제됩니다. 계속할까요?") → 확정 시 로컬 파일 즉시 삭제, 서버 업로드 없음.
- **결과**: 대시보드로 복귀, 회의 카드 생성되지 않음.
